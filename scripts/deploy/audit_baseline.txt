# so the list cannot silently drift from what the scanner actually reports.
#
# Why a baseline exists at all
# ----------------------------
# requirements-deploy.txt = the serving pin set PLUS MLflow and pyarrow, because this
# container serves through the real registry architecture (aliases, promotion, rollback)
# and runs the first-deploy bootstrap. MLflow is pinned to the exact version the
# platform's tracking/registry behaviour is tested against (requirements-dev.txt), so the
# image runs the dependency set the test suite verifies rather than an untested one.
#
# Exposure analysis (why these are accepted for this deployment, for now)
# ----------------------------------------------------------------------
# * MLflow is imported IN-PROCESS. This deployment runs no MLflow server: no MLflow HTTP
#   listener exists in the container, no MLflow port is exposed, and the tracking store is
#   a SQLite file on the private persistent disk. A large share of MLflow advisories
#   concern the tracking/UI server's request handling and its auth paths, neither of which
#   is reachable from the internet here.
# * pyarrow is pulled in by MLflow for Parquet artefact logging. The only artefacts are
#   joblib bundles written by this project's own training run; no untrusted Parquet file
#   is ever parsed.
# * cryptography is used by MLflow's auth helpers, which are unused: there is no MLflow
#   authentication in this topology, and TLS terminates at Render's edge.
#
# Remediation path (tracked, not forgotten)
# -----------------------------------------
# Upgrading MLflow to >=3.15.0 clears the large majority of the ids below. That upgrade is
# deliberately NOT bundled into a deployment commit: it changes the library whose registry
# semantics this platform's evidence was produced with, so it belongs in its own change
# that re-runs the full suite and re-records any affected evidence. The ids marked
# NO FIX are not remediable by an upgrade at all and must be revisited if this deployment
# ever exposes an MLflow server or accepts MLflow input from untrusted callers.
#
# Gate semantics (enforced in .github/workflows/ci.yml)

# * The CI log prints every finding for the deployment set BEFORE applying this list.

#   acceptance with a re-review trigger -- not a disabled check.
